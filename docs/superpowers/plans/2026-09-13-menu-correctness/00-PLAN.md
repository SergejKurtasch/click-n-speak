# Исправление меню Click-n-speak: план по эпохам

> Для исполнителя: применять навык `executing-plans`, выполнять одну выбранную эпоху по её флажкам. Этот документ разрешает планирование; реализация начинается по отдельному запросу пользователя. По умолчанию работать последовательно одним агентом на Sol.

**Цель:** привести все 16 пунктов меню и вложенные команды к описанному пользователю поведению, устранить потерю правок и ошибки управления состоянием.

**Архитектура:** сохранить SwiftPM-пакеты и существующих владельцев данных. Меню отправляет намерения и показывает состояние; AppDelegate/координаторы управляют жизненным циклом, DictionaryCoordinator — словарём, SessionController — записью и файлами. Извлекать только небольшие роли, необходимые для исправления и тестирования конкретного дефекта.

**Стек:** Swift 6, macOS 14+, AppKit/SwiftUI, AVFoundation, Security.framework, ServiceManagement; Python только в проектном `venv` для существующих проверок и вспомогательных скриптов.

**Спецификация:** разделы «Контракты поведения» и «Матрица покрытия» настоящего документа; требования конкретной эпохи уточняют их. Актуальный AGENTS.md обязателен. Старые планы миграции описывают историю, а не незавершённую работу этой серии.

**Исходный снимок:** HEAD `045d997`, 2026-09-13. До планирования уже изменены AGENTS.md, PopupPlacement.swift, PreviewPanel.swift, PreviewPanelTests.swift; существуют пользовательские незакоммиченные файлы PreviewPanelSizing.swift и каталоги прежней стабилизации. Не включать их в коммиты эпох автоматически.

## Как соотнести эпоху с пятичасовым лимитом Sol

План разбит на **10 небольших эпох**, каждая — законченный результат с собственным тестовым барьером. Это оценка объёма инженерной работы, а не обещание фиксированного расхода токенов или пяти часов непрерывной работы.

Расход пятичасового окна зависит от тарифа, модели, контекста, рассуждений и инструментов; одинаковые по длине запросы расходуют разный объём. API-цены и размер контекстного окна нельзя использовать как бюджет подписки. Источник: [официальная документация OpenAI](https://learn.chatgpt.com/docs/pricing), проверено 2026-09-13.

Практические правила выполнения:

1. Начинать эпоху с доступного окна лимита и читать только AGENTS.md, этот документ, выбранную эпоху и относящийся к ней код. Не перечитывать всю миграцию.
2. Если доступен инструмент лимитов, зафиксировать использованный процент в начале и после первого законченного блока. Отсутствующее значение не считать нулём. Не покупать кредиты и не использовать сброс без запроса пользователя.
3. Плановый резерв: около **30% доступного в начале ресурса** на проверки, ревью и исправление регрессий. Это организационное правило, не оценка внутреннего биллинга.
4. Не начинать второй крупный блок, если первый израсходовал большую часть окна. Закончить проверяемый результат и продолжить оставшиеся флажки после следующего окна. Неполную эпоху не объявлять завершённой.
5. Для тяжёлых эпох 01, 05, 06, 07 и 09 предусмотрена граница A/B. A и B при необходимости выполняются в разных окнах; тесты и критерии не сокращаются.
6. После первых двух эпох откалибровать последующие по фактическому расходу. Маленькую эпоху 02 можно закончить раньше; оставшееся время не превращать в неограниченное расширение задачи.
7. После каждой эпохи дать краткий результат в чате: что изменено, команды и исход проверок, остаток работы, следующий файл. Не создавать отдельные summary-файлы.

## Глобальные ограничения

- Планы и сообщения — русский; Swift/Python-код, комментарии, имена тестов и коммиты — English.
- Перед любым запуском тестов: `source venv/bin/activate`. При отсутствии venv сначала восстановить среду, а не запускать тесты системным Python.
- Не переписывать Python-референс и не добавлять зависимости без необходимости.
- Не расширять сборку до общего рефакторинга MenuBarController, AppRuntimeCoordinator или DictionaryCoordinator.
- Сохранить JSON schema 10 и неизвестные поля, если задача не содержит обоснованного отдельного изменения схемы. План ниже обходится без новой обязательной миграции.
- Сохранить разделение active/desired runtime, атомарную замену пары STT/editor, snapshot текущей записи, terminal shutdown и ожидание persistence.
- Не возвращать Input Monitoring в native Swift и не переносить запрет Python/pynput на Carbon автоматически.
- В автоматических тестах использовать временные данные, fake HTTP/Keychain/process adapters; не читать настоящие ключи и не посылать транскрипты во внешние API.
- Реальные удаление моделей, установка приложения и изменение внешних настроек выполняются только в согласованном ручном сценарии. План не является командой выполнить эти действия сейчас.
- Не запускать сборку со сбросом пользовательских TCC. Для согласованной проверки bundle явно применять `CNS_RESET_TCC_AFTER_BUILD=0`; стандартную политику скрипта не менять.
- Изоляция Git выбирается в начале реализации. Не применять `reset --hard`, не убирать неизвестные файлы, не делать `git add .`.
- Перед коммитом проверить .gitignore и staged diff на секреты; Conventional Commits. После успешного коммита выполнить `update-Codex-md`, меняя карту только при изменении контрактов.
- Перепроверить каждое замечание регрессионным сценарием. Предыдущий аудит — трассировка кода и существующие тесты, а не воспроизведение всех ошибок на установленном приложении.

## Контракты поведения

### C01. Перезапуск и выход

Перезапуск создаёт ровно один новый процесс после полного выхода старого; блокировка единственного экземпляра остаётся у старого до успешного drain. Отказ завершения не порождает отложенный неожиданный запуск. Обычный выход никогда не создаёт новый процесс.

### C02. Разрешения и мастер

После фактически полученных разрешений и готовности STT горячая клавиша регистрируется один раз. Повторное открытие меню не дублирует регистрацию. Ручной вызов мастера всегда даёт видимый результат; это мастер разрешений, не новый мастер выбора всех моделей и ключей.

### C03. Панели словаря

Фоновый refresh сохраняет введённые, но не сохранённые правки. Изменение той же строки извне обнаруживается как конфликт. Ошибка статистики не изображается как измеренные нулевые показатели; ошибка сохранения термина — как дубликат. Ошибки изменения режима и анализа предложений видны пользователю. Закрытие/открытие существующей панели не является неявным сбросом черновика.

### C04. Откат терминов

Один откат возвращает предыдущую содержательную операцию для явно выбранного языка. Пустой прежний словарь — допустимый снимок. Пакет из нескольких принятых кандидатов сохраняет один снимок на язык до всего пакета. Метрики и счётчики использования не стирают undo. Откат терминов не отменяет разрешения/запреты замен и не переписывает историю фраз.

### C05. Ключи и восстановление

Предлагаемый основной вариант: **честная кнопка «Сохранить»**, проверка локального формата и отдельное описание «Работоспособность проверяется при обращении к сервису». Не добавлять тестовый платный запрос ради исправления подписи. Ключ из окружения обозначается как источник фактического ключа; сохранение/очистка Keychain не выдаётся за изменение environment. Recovery открывает провайдера и модель, указанные в ошибке.

Это сознательный выбор из двух вариантов: реальная серверная проверка потребовала бы отдельного продуктового контракта (проверка авторизации не доказывает доступ к конкретной модели, квоты и STT). Если пользователь впоследствии потребует «Сохранить и проверить», сделать отдельную эпоху с provider-specific запросами и результатами authenticated/denied/unavailable; не включать её скрыто в текущую оценку.

### C06. Удаление моделей

Удаляются только модели, для которых нет активного, подготавливаемого, удерживаемого старым сервисом или загрузочного использования. Проверка и начало удаления согласованы с владельцами этих операций. Список диалога не является окончательной проверкой. Ошибка удаления видна пользователю; успешное удаление корректно обновляет доступность.

### C07. Перечитывание конфигурации

Поддерживаемые параметры нарезки меняются для следующей записи; текущая запись использует старые значения до конца. Вся четвёрка параметров валидируется вместе. Невалидный внешний config не вызывает частичного применения словаря или новых runtime-настроек. Язык интерфейса остаётся restart-required и обозначается именно так.

### C08. Файловое редактирование

Успех STT и результат AI-редактирования различаются. Полученный текст сохраняется при skipped/disabled/error/timeout редактора, но UI сообщает, что улучшение не выполнено. `.unchanged` считается успешным выполнением без изменений. Cancel остаётся cancel и не превращается в warning-success. Copy/Save сохраняют только текст.

### C09. Обновление приложения

Модели и приложение имеют независимые progress panels и отмену. Запоздалый callback не меняет новую операцию. Ошибка подготовки установки видна и допускает повтор; целостность, подпись, durable swap и rollback не ослабляются. «Позже» сохраняет понятный способ установить уже подготовленную версию в текущем процессе. Отказ shutdown отменяет ожидающий update handoff; будущий обычный Quit не становится неожиданной установкой.

### C10. Остальные команды

Основные/дополнительные языки, история по 5 строк, полное копирование фразы, About и системный автозапуск сохраняют рабочую семантику. В AI-подменю добавить явное «Выключен»; повторный выбор уже активного backend становится идемпотентным. Это небольшой намеренный UX-переход, а не исправление якобы случайного прежнего toggle.
